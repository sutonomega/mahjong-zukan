# 初心者向け学習サービス — 機能仕様書（案）

この仕様書は Issue #8・#9 の初版であり、[サービス概要と初回公開範囲](service-scope.md) を前提にする。新しい学習サービスを主役にし、既存の麻雀図鑑を専門用語の補助辞典として利用する。

## 1. 目的と対象

麻雀初心者が、牌と基本形、1局の流れ、入門役を順に学べるようにする。利用者はアカウント登録せず、スマートフォンまたはPCのブラウザーから利用する。

初版の学習範囲は4人打ちの一般的なリーチ麻雀を前提とする。ローカルルール差を含む説明は前提を明示する。

## 2. 情報構造と役割

### 主役となる学習サービス

- **学び始める**：初級コースの目的、進捗、最初のステップを表示する。
- **学習ステップ**：短い解説、牌姿または例、前後のステップ、関連用語・役へのリンクを表示する。
- **確認問題**：コース内容に対応する選択式の短い問題と回答解説を表示する。
- **使い方**：コースと学習状態の保存に関する案内を表示する。

### 補助となる既存の麻雀図鑑

- 用語・役の一覧、検索、カテゴリ絞り込みを引き続き提供する。
- 学習文中の専門用語に短い吹き出し説明と、詳しい用語ページを提供する。
- 学習サービスから図鑑を開いた後、元の学習位置へ戻れるようにする。

## 3. 学習コースの順序（初版案）

1. 麻雀で使う牌を知る：数牌・字牌
2. 牌の組み合わせを知る：順子・刻子・雀頭
3. アガリの形を知る：基本形と例外の入口
4. 1局の流れを知る：配牌、ツモ、打牌、鳴き、テンパイ、アガリ
5. アガリに必要な役を知る：役がないとアガれない基本
6. 最初に覚える役：リーチ、タンヤオ、役牌
7. 確認問題：牌、基本形、ゲーム進行、入門役を振り返る

各ステップの文章・図・問題はコンテンツ設計・校閲ガイドに従う。難易度や順序は既存 Issue #6 のレビュー結果を反映する。

## 4. 機能要件

### 4.1 コース開始と移動

- トップまたは主ナビゲーションから学習開始地点へ移動できる。
- 学習サービスのトップでは、まず学習コースと続きから学ぶ操作を案内する。
- 図鑑への入口は補助機能として配置し、学習コースへの導線を主にする。
- コース画面でステップの順序と各ステップの完了状態を把握できる。
- ステップに「前へ」「次へ」の移動操作を用意する。
- 最終ステップでは、次の学習または図鑑での調べ方を案内する。
- 学習ページから図鑑項目を開いた後、画面上の戻る操作で元の学習ページとスクロール位置に戻れる。

### 4.2 専門用語と図鑑の連携

- 学習文中で説明が必要な専門用語は、図鑑データの安定した項目IDに関連付ける。
- 学習文に用語が登場したら、本文上で用語リンクとして表示する。
- ポインターを用語リンクに重ねると、図鑑の短い説明を吹き出しで表示する。
- キーボードフォーカスでも同じ説明を表示し、タッチ端末では用語をタップして説明を確認できる。
- 用語リンクをクリックまたはタップすると、その用語の詳細ページを開く。
- 詳細ページから戻ると、直前の学習内容とスクロール位置を復元する。
- 学習文に必要な用語が図鑑に未登録の場合、先に用語・読み方・短い定義・詳細説明を図鑑データに追加する。
- 吹き出しは初学者がその場で読み進めるための短い説明とし、条件・例・注意事項など詳しい内容は詳細ページに置く。
- 専門用語リンクは一般語の一部に誤って付かないよう、登録用語の境界と表記ゆれを校閲する。

既存の図鑑コンポーネントを同一アプリ内で再利用するか、既存図鑑の詳細ページへ遷移させるかは技術設計で決める。どちらの場合も、用語IDと戻り先を安定して扱う。

### 4.3 学習済みと進捗

- 利用者は学習ステップを完了済みにでき、完了状態を解除できる。
- 進捗は完了ステップ数と全ステップ数で表示する。
- 進捗は利用中のブラウザー内に保存し、ログインは求めない。
- 既存の図鑑学習状態（保存キー `mahjong-zukan-learned`）を維持する。新しいコース状態は別キーに保存し、既存データを上書きしない。
- 保存内容が不正または読めない場合は初期状態で利用を継続し、学習ページ自体は利用可能にする。
- 保存データの削除や端末間同期は初版では提供しない。使い方ガイドにブラウザー内保存であることを説明する。

### 4.4 確認問題

- 問題は1問ずつ表示し、選択式を基本とする。
- 回答後、正誤だけでなく、判断の理由と対応する学習内容へのリンクを表示する。
- 回答後に別の選択肢を選び直せるか、再挑戦の操作を明示する。
- 初版では得点ランキングや連続正解記録を設けない。
- 回答履歴の永続保存はせず、進捗の完了状態とは分けて扱う。

### 4.5 使い方・アクセシビリティ

- 主な操作はリンクまたはボタンとして表し、キーボードで操作可能にする。
- 問題の正誤は色だけで伝えず、文字でも示す。
- 牌姿の図はテキスト説明を添え、重要情報を画像だけに閉じない。
- 学習状況が空の場合、エラーではなく開始方法を表示する。

## 5. データ設計（初版案）

- `Course`：コースID、タイトル、説明、ステップIDの順序。
- `Lesson`：ステップID、タイトル、本文、図・例、関連する用語・役ID、完了条件。
- `GlossaryEntry`：既存図鑑の安定ID、用語名、読み方、短い吹き出し説明、詳細説明、関連語、出典。
- `Question`：問題ID、対象Lesson ID、設問、選択肢、正答ID、解説。
- コース・記事・問題のコンテンツは静的データとして管理する。
- 画面表示名ではなく安定したIDで関連付ける。用語リンクの表示は登録名称と別名を使う。
- コース状態はバージョン番号と完了Lesson IDの配列を持つ。データ形式を変える際は読み込み時の互換性を考慮する。

具体的な型、保存キー、コンポーネント境界、既存図鑑との接続方法は `doc/design.md` と実装書に反映する。

## 6. 非機能要件

- 主な利用経路はスマートフォン幅で横スクロールなしに閲覧できる（牌姿など表形式の補足を除く）。
- 学習記事の見出し・文章・図の代替説明を適切に構成する。
- 用語吹き出しはマウス、キーボード、タッチ端末のいずれでも内容を確認できる。
- 基本ページは既存の静的サイトとGitHub Pagesの構成に合わせる。
- 読み込みにサーバーAPIを必要としない。
- 既存の図鑑検索、用語リンク、詳細ページ、習得済み記録を壊さない。

## 7. 完了条件

- 初級コースの画面とステップ順が仕様に沿っている。
- 学習文に含まれる専門用語が図鑑に登録され、本文から参照されている。
- ホバーまたはフォーカスで短い説明が吹き出し表示される。
- 用語を選択すると詳細ページが開き、戻ると学習位置が復元される。
- 学習済み状態が同じブラウザーで再読み込み後も保持される。
- 問題に回答すると、正誤・理由・学び直し先が分かる。
- 使い方ガイドに保存方式と用語リンクの使い方が説明される。
- 実装後、仕様と画面・保存形式の差分を文書へ反映する。

## 8. 決定が必要な事項

- 各コースのステップ数・問題数は、コンテンツ量の見積もり時に決定する。
- コース開始ページの名称・ナビゲーション位置は画面設計で決める。
- 既存図鑑を同一アプリ内で使うか、ページ遷移でつなぐかは技術設計で決める。
- 点数計算と戦略講座は初版対象外。学習者のフィードバックをもとに別途判断する。
