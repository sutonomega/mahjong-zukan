# 再利用可能な学習プラットフォーム — 機能仕様書（案）

この仕様書は、分野に依存しない学習基盤と、麻雀を初期教材とするコンテンツパックの振る舞いを定義する。コース機能と図鑑・用語辞典機能は単体でも利用でき、設定された連携方法がある場合に連動する。

## 1. 目的と利用者

初学者が短いレッスンを順に学び、専門語の意味をその場で確認し、問題で理解を確かめられるようにする。初期教材は4人打ちの一般的なリーチ麻雀を前提とする。

## 2. 機能構成

### 学習コース機能

- コース一覧、コース概要、レッスン、前後移動、完了状態と進捗表示を提供する。
- レッスンは文章、図、例、用語参照、任意の分野拡張データで構成する。
- 問題は設問、選択肢、正答、理由、復習先を持つ。
- 教材パックを読み込めば、その分野の専用アプリやサービスへ移植できる。

### 図鑑・用語辞典機能

- 用語・概念の一覧、検索、カテゴリ絞り込み、詳細ページを提供する。
- 項目に別名、読み方、短い定義、詳細説明、関連項目、出典を設定できる。
- 単体で動作し、学習コースを必要としない。
- 用語データのパックを差し替えて異なる分野に使える。

## 3. 初期麻雀コース案

1. 牌の種類：数牌・字牌
2. 牌の組み合わせ：順子・刻子・雀頭
3. 基本のアガリ形
4. 1局の流れ：配牌、ツモ、打牌、鳴き、テンパイ、アガリ
5. アガリに必要な役
6. 入門役：リーチ、タンヤオ、役牌
7. まとめと確認問題

教材の学習順序・説明・図・例題は、プラットフォーム共通ロジックから分離して教材パックで管理する。

## 4. 機能要件

### 4.1 コース・レッスン

- 利用者はコース一覧からコースを選び、最初の未完了レッスンから開始または再開できる。
- コース概要で目的、順序、完了状態を確認できる。
- レッスンに前へ・次へ・完了の操作を用意する。
- レッスン本文から用語のプレビューと詳細を開き、戻ったときにレッスン位置を復元できる。
- コース機能単体でも、パックに同梱された用語スナップショットを使って一通り学習できる。

### 4.2 用語・概念の連携

- 本文中の専門用語は、パック名前空間を含む安定IDで用語項目へ関連付ける。
- 用語リンクへのホバーまたはキーボードフォーカスで、短い定義を吹き出し表示する。
- タッチ端末ではタップで定義を確認でき、別操作で詳細を開ける。
- 選択すると設定済みの用語詳細ページを開き、戻る操作でレッスンとスクロール位置を復元する。
- 用語辞典が連携されている場合は辞典の最新データを優先する。連携できない場合はコースパックに含まれる同じIDの短い定義・別名・簡易詳細を使う。
- 用語辞典のURL形式はリンク解決設定で差し替えられる。URLが設定されていない場合は同梱の簡易詳細を表示する。
- 用語項目が見つからないIDは分かりやすく検出し、本文を読めなくしない。
- 用語の境界・別名は用語辞典データから生成し、一般語への誤リンクを抑える。

### 4.3 問題と復習

- 問題は選択式を基本とし、回答後に正誤・理由・対応レッスンを表示する。
- 回答履歴は初版では永続保存しない。
- 問題の文面・正答・解説は教材パック側で管理する。
- 結果は色だけに依存せず、テキストでも伝える。

### 4.4 進捗保存

- コース完了状態は利用中のブラウザーに保存し、ログイン不要で利用できる。
- 保存キーはプラットフォームID、パックID、コースIDを名前空間として含め、異なるサービス間で衝突しないようにする。
- 保存データはスキーマバージョンと安定したレッスンIDの一覧を持つ。
- 不明なバージョンや不正なデータの場合、初期状態から学習を続けられる。
- サーバー保存や端末間同期は初版では提供しない。
- 用語辞典の習得状態を使う場合は、コース進捗とは独立した連携アダプターを通す。

### 4.5 アクセシビリティと表示

- 主な操作はリンクまたはボタンとして表し、キーボード操作とフォーカス表示に対応する。
- 牌姿など分野固有の図には、教材パックが代替テキストを提供する。
- 小さな画面でも主要な学習経路を横スクロールなしに利用できる。
- 動作が空・読み込み失敗・連携先不在の場合も、教材パック内の内容で学習を続けられる。

## 5. データ契約と再利用要件

### 5.1 共通パック情報

すべての教材パック・用語辞典パックは次のメタデータを持つ。

- packId：一意で安定した名前空間
- title と description
- locale
- schemaVersion：データ契約のバージョン
- contentVersion：パック内容のバージョン
- sources：出典、ライセンス、確認日
- extensions：任意の名前空間付き・バージョン付き追加データ

IDは例として mahjong:riichi や science:gravity のようにパック内で一意となるようにする。表示名・読み方をIDとして使わない。

### 5.2 コースパック

- Course：ID、タイトル、説明、順序付きLesson ID。
- Lesson：ID、タイトル、本文ブロック、図・例、用語ID、完了条件。
- Question：問題ID、対象Lesson、設問、選択肢、正答、解説、復習先。
- 本文ブロックは段落、見出し、用語参照、画像、表などの共通形式を基本とする。
- 分野固有のブロックは拡張形式で提供し、未知のブロックは代替テキストで表示して読み飛ばせる。

### 5.3 用語辞典パック

- GlossaryEntry：ID、用語名、別名、読み方、短い定義、詳細説明、カテゴリ、関連ID、出典。
- 短い定義は吹き出し用、詳細説明は独立ページ用とする。
- IDは表示名から独立させ、用語名を修正しても参照が切れないようにする。

### 5.4 連携インターフェース

コース機能と用語辞典機能の接続は、次の機能を持つアダプターで行う。

- packIdとentryIdから用語の短い定義・別名・詳細への参照を取得する。
- packId、entryId、returnToから詳細ページのURLを解決する。
- 任意でパック内の用語を検索する。
- 連携先なしの場合はコースパックのスナップショットにフォールバックする。

アダプターはHTTP、埋め込みデータ、別ページ遷移などの実装方式に依存しない。コース本体と辞典本体は相手のUIフレームワークや内部保存方式に直接依存しない。

## 6. 非機能要件

- コース・用語辞典とも静的データとして配布でき、サーバーAPIを必須としない。
- パック形式はバージョン管理し、移植先で検証できる。
- 分野固有の文章・図・ルール条件を共通コードへ直書きしない。
- ロケールごとに文章・表示名を差し替えられる。
- パックに含む画像・資料のライセンスと出典を追跡できる。

## 7. 完了条件

- 初級麻雀コースをパックデータとして読み込み、所定の順で学べる。
- 学習文中の専門用語でホバー・フォーカス・タップにより吹き出し説明を確認できる。
- 用語詳細を開いてからレッスン位置へ戻れる。
- 用語辞典が未接続でも、同梱データでコースを完了できる。
- 図鑑・用語辞典は単独で一覧、検索、詳細を利用できる。
- 非麻雀分野のサンプルパックを追加し、共通画面と進捗機能が使える。
- 用語・コース・進捗IDがパック間で衝突しない。
- 各パックを別アプリまたはサービスへ移す際、分野固有コード以外の共通機能の書き換えを要しない。

## 8. 決定事項

- 初期麻雀コースは4人打ちの一般的なリーチ麻雀を扱う。
- パックの格納形式、URL連携方式、拡張機構の具体的な型は設計書で定める。
- 非麻雀分野のサンプル教材は、共通仕様検証用の最小内容とする。
- 点数計算や戦略講座の追加時期は初回公開後に判断する。
