# 再利用性の事前検証

Issue #25の実装前に、`dev` の共通契約と画面構成を確認しました。この記録はコードの動作確認ではなく、現行実装の静的な構造確認です。別分野の教材パックを実際に表示した結果とは区別します。

## 確認結果

| 対象 | 現状 | 判断 |
| --- | --- | --- |
| コース・レッスン・問題 | `LearningPack`、`LearningCourse`、`LearningLesson`、`LearningQuiz` は分野中立の型です。 | 他分野の教材データを表現できる契約があります。 |
| 用語参照 | `GlossaryReference` は名前空間付きID、ラベル、短い説明を持ち、コースと問題から参照できます。 | 用語辞典を接続しない場合にも短い説明を表示できます。 |
| コース表示 | `CoursePlayer` はパックとコースを受け取り、段落・要点・手順・拡張ブロックと問題を表示します。 | 共通ランタイムとして再利用できる形です。 |
| 進捗 | 保存キーにパックIDとコースIDを含め、レッスンIDを照合します。 | 別パック間で進捗が混ざらない設計です。 |
| 検索と言語 | 検索パックにパックIDとロケールを持ち、正規化・分割器を差し替えられます。 | 他ロケールや他パックに対応できる拡張点があります。 |
| 用語辞典単独利用 | 用語項目の共通契約と共通の辞典表示機能はありません。現在の一覧・詳細・カテゴリ・習得状態は麻雀の `Entry` データと `App` に結びついています。 | Issue #25の「用語辞典単独利用」は未達です。 |
| コース単独利用 | `CoursePlayer` の用語クリックは必須コールバック経由で、親アプリが遷移先を解決します。 | 辞典なしでも学習できますが、単独アプリとしての起動・画面構成は未検証です。 |
| 別分野の拡張表示 | 拡張レンダラーはパック側で登録できます。現在のアプリ登録は麻雀拡張のみです。 | 未知の拡張の代替テキストは共通側で扱えますが、他分野の拡張は未検証です。 |

## Issue #25の進め方

完了条件を満たしたとは判断しません。Issue #25は開いたままにし、次の順で検証します。

1. 用語項目・用語辞典パックの共通契約と、コースなしで使える共通辞典表示を用意します。
2. 麻雀以外の小さな教材パックに、用語・コース・レッスン・問題を定義します。
3. 分野固有の条件分岐を共通ランタイムへ追加せず、コースと辞典をそれぞれ表示します。
4. 用語プレビュー、詳細への遷移、ロケール検索、パック・コース別進捗を動作確認します。
5. 単独表示と統合表示の結果、未対応事項をこの記録に追記します。

## サンプル実装

別分野の植物観察パックを `src/content-packs/botany/sample-pack.ts` に追加し、コースと図鑑の内容を麻雀データから独立させました。表示確認用に `?demoPack=botany` を指定すると、共通のコースプレイヤーと独立した図鑑プレイヤーを切り替えられます。コース内の用語参照から図鑑詳細へ移動でき、進捗は既存のパックID・コースID単位の保存を利用します。

この実装で単独表示の経路を用意しましたが、ブラウザー上での実行確認はまだ行っていません。独立配布のビルド、異なるロケールでの検索、デプロイ後のURL遷移も未検証です。Issue #25はこれらの確認を終えるまで開いたままにします。
