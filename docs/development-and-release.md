# 開発・公開・コンテンツ更新手順

この文書は、開発環境の起動、変更の確認、GitHub Pagesへの公開、および学習コンテンツの更新手順をまとめたものです。ブランチ運用とレビュー手順は [プロジェクトワークフロー](project-workflow.md) を参照してください。

## 開発環境

### 必要なもの

- Node.js 24（GitHub Actionsのビルド環境と合わせます）
- npm（Node.jsに付属）
- Git

### 起動

リポジトリのルートで以下を実行します。

1. 依存パッケージをインストールします: `npm install`
2. 開発サーバーを起動します: `npm run dev`
3. ターミナルに表示されたローカルURLをブラウザーで開きます。通常は `http://localhost:5173/` です。

開発サーバーを終了するには、起動したターミナルで Ctrl+C を押します。

### 変更の確認

- 型の検査と本番向けビルド: `npm run build`
- ビルド成果物をローカルで表示: `npm run preview`

GitHub Actionsの公開ワークフローは、Node.js 24で依存パッケージをインストールしてから、GitHub Pages用のパスを指定して `npm run build` を実行します。公開前の変更では、少なくともビルドが成功することを確認してください。画面や操作を変更した場合は、変更箇所に応じてPC・スマートフォン幅、キーボード操作、用語リンクを確認します。

## コンテンツの更新

### 用語・役

- 用語・役の一覧と表示内容は `src/data/entries.ts` で管理します。
- 項目を追加するときは、既存IDと重複しないIDを割り当てます。
- Excel由来の項目では、元の値を確認できる `source` を保持します。Excelにない補足項目は補足データとして区別します。
- 説明文で既存の用語を使うと、その用語は吹き出しと詳細ページへのリンクになります。関連する用語が期待どおり認識されることを確認してください。
- 用語・役の登録方法や表示項目の詳しい設計は [実装書](implementation.md) を参照します。

### 学習コース・レッスン

学習コースのデータは `src/content-packs/` 以下に置きます。レッスンの追加・変更時は、コースIDとレッスンIDの一意性、表示順、理解度チェック、本文に含まれる用語リンク、進捗保存への影響を確認してください。共通コース機能に関わる変更は `src/platform/` を確認し、麻雀以外でも再利用できる設計を維持します。教材の書き方は [学習コンテンツ作成ガイド](learning-content-authoring.md) を参照します。

### Excelからの初期データ取り込み

初期データの元ファイルはワークスペース上の `麻雀説明.xlsx` です。ファイルを用意したうえで、Pythonと `openpyxl` を利用して `python scripts/import_excel.py` を実行すると、`src/data/mahjongData.json` を生成できます。変換後は差分を確認し、画面に表示する値や補足説明の更新が必要な場合は対応するデータも確認します。取り込みスクリプトは元のExcelファイルを変更しません。

## GitHub Pagesへの公開

### 初回設定

GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。公開先はGitHubリポジトリのPages設定で確認します。

### 公開の流れ

- `dev` は開発用ブランチです。ここへのpushだけでは公開されません。
- `main` へのpushで `.github/workflows/deploy.yml` が起動し、ビルドとGitHub Pagesへのデプロイを行います。
- Actions画面からワークフローを手動実行することもできます。
- デプロイ成功後、Pages設定に表示されるURLを開き、ホーム、学習コース、図鑑、直リンク、再読み込みを確認します。

GitHub ActionsではUbuntu 24.04とNode.js 24を使い、リポジトリ名を含む公開パスを指定してビルドします。ローカルの `npm run build` とは公開用のbase path指定が異なる点に注意してください。

## 公開前チェック

- [ ] `npm run build` が成功する
- [ ] 学習コースの開始、レッスン移動、理解度チェックが動く
- [ ] 図鑑の検索、種類・カテゴリ絞り込み、詳細表示が動く
- [ ] 用語の吹き出しに説明が表示され、選択すると該当する詳細へ移動する
- [ ] 進捗が再読み込み後も表示される
- [ ] 小画面で本文、牌姿、ナビゲーションが利用できる
- [ ] キーボードで主要な操作ができ、フォーカス位置が見える
- [ ] 公開URLで直リンクと再読み込みができる
- [ ] サイト上に不要な外部リンクがなく、必要な参考情報は最小限である

問題が見つかった場合は、対象画面・操作・再現手順を記録してIssueで管理します。

## フィードバックの受付と公開後対応

GitHubリポジトリの **Issues → New issue** に、次のフォームを用意しています。

- **不具合の報告**: 対象ページまたは用語、URL、再現手順、実際の結果、期待する結果、端末・ブラウザーを記録します。
- **説明・教材へのフィードバック**: 対象の用語・役・コース・レッスン、分かりにくい点、任意の修正案を記録します。

Issueは公開されるため、報告者には個人情報・ログイン情報などを記入しないよう案内します。運用担当者は新しい報告を確認し、再現性と対象を確認して対応Issueまたはコンテンツ修正に結び付けます。修正後は該当画面と公開環境を再確認し、Issueに結果を記録します。
