# 学習教材パックの作成ガイド

このガイドは、麻雀以外の分野でも利用できる学習コースデータの編集ルールです。教材本文・図・用語参照・出典を、画面表示の実装と分けて管理します。

## 基本構造

- `LearningPack` は分野別コンテンツの単位です。分野を識別する `packId`、表示用メタデータ、スキーマ版、コンテンツ版、コース一覧を持たせます。
- `LearningCourse` は順序を持つレッスンのまとまりです。
- `LearningLesson` は見出し・要約・教材ブロック・任意の出典一覧を持ちます。
- `LessonBlock` は段落、要点コールアウト、手順、図などの拡張ブロックで構成します。
- `LessonSegment` は文章と用語参照を分けます。専門語は表示文字列だけで済ませず、安定IDの `GlossaryReference` に結びつけます。

ドメイン固有の牌・医療器具・楽器などを共通契約に追加せず、必要な図は名前空間付きの拡張レンダラーとして定義します。共通の本文や用語リンクだけで表せる内容には、独自拡張を増やしません。

## 図とアクセシビリティ

図を使うときは `LessonExtension` にレンダラーID、スキーマ版、説明テキスト、JSON形式のペイロードを指定します。レンダラーIDには `mahjong.` や他分野の名前空間を付け、別分野の実装と衝突しないようにします。

`altText` は図を見なくても学習上の結論が分かる文章にします。図中のラベルや例は、本文でも必要な範囲を説明し、図だけに重要な条件を閉じ込めないでください。

## 用語参照

用語IDはコンテンツパックの名前空間を含めます（例：`mahjong:term-066`）。本文中の表示語、短い説明、遷移先の辞典項目を同じIDに揃えます。IDを変更する場合は参照元も一緒に更新します。

## 出典と前提

外部資料に基づくレッスンでは、レッスンの `sources` に次を記録します。

- 安定した出典ID
- 資料名
- 直接参照できるURL
- 確認日（`YYYY-MM-DD`）

ルール差や対象読者による前提は、出典メタデータだけに隠さず、該当レッスン内にも平易な文章で明記します。たとえば麻雀では「日本の一般的なリーチ麻雀を前提とする」「鳴いた断幺九を認めるルールを想定する」のように、成立条件に関わる前提を書きます。別ルールを採用する場合は教材文と例を見直します。

## 内容の確認

教材を追加・更新するときは、次を確認します。

1. 初学者が専門語を知らなくても、段落と例の順に読める。
2. 成立例と注意例を区別し、例が説明した条件を満たす。
3. 専門語は正しい辞典IDへリンクされている。
4. 図の説明文、本文、用語説明の間に矛盾がない。
5. 出典URLと確認日が記録され、ルールや対象範囲の前提が明記されている。
6. 変更箇所をPR本文に短い差分として示し、レビュー対象を追いやすくする。


## 検索インデックス

検索は本文データから独立した `SearchablePack` を使います。共通検索には、パックID・ロケールと、各項目の安定ID・種類・見出し・別名・読み・カテゴリ・説明を渡します。分野固有の検索画面や辞典画面に依存しません。

`learningPackToSearchPack` は、コース・レッスン見出し、要約、段落、手順、用語参照、図の説明を検索用項目へ変換します。用語辞典が未接続でも教材本文から検索結果を作れます。辞典を接続するときは同じパックIDの検索項目を追加し、種類やカテゴリなどは任意のファセットとして保持します。

検索時には対象パックIDを指定できます。見出し・別名・読み・カテゴリは正規化後の完全一致で探し、説明文はロケール別の単語分割後に単語または単語列が完全一致した場合だけ結果に含めます。部分一致や誤字候補は出しません。日本語ではひらがな・カタカナを同じ検索表記に正規化します。読みの値は `/` と `／` で分割してから検索するため、「ツーパイ／ジハイ」はどちらでも一致します。言語ごとの分割器や正規化処理は差し替えできます。検索結果からどの画面を開くかは、サービス側が項目の種類と安定IDで決めます。
